# 模块边界与复用。

本项目为 L 档，多宿主、多服务器协议、并发诊断和资产生命周期形成真实复杂度。
抽象正当理由是隐藏协议与存储细节，以及隔离进程、文件系统、时间和身份依赖以覆盖失败与时序。
不新增只做转发的 Service、Repository 或工厂层。

| 模块 | 责任与边界 |
|---|---|
| Core、state | 工作区与 LS 实例、启动互斥、代次、文档同步、崩溃恢复及有界关闭。 |
| semantic | 能力检查、九操作协议编排、坐标校验、调用层级候选和大结果分页。 |
| diagnostics、diagnostic-value、feedback | 自有诊断契约、版本与通道可信度、线程基线、投递记账和完整文本预算。 |
| workspace、file-events | 磁盘扫描游标、内容摘要、监听与文件协议事件过滤。 |
| configuration、server-configuration | 持久化、锁与备份、项目内容信任、服务器字段验证及覆盖优先级。 |
| assets、catalog | 私有安装事务、固定来源、完整性、所有权、共享消费者及安全卸载。 |
| runtime、process-identity、guard-leases | 本机 Core 控制鉴权、进程启动身份及资产使用租约。 |
| guard、client-binding | 每 LS 私有管道与 EOF/强杀后有界收尾，两个宿主共用绑定。 |
| mcp | MCP 边界、宿主 threadId 校验、Hook JSON 文本契约及有界输入。 |
| pi | Pi 工具、事件、renderer、状态和管理入口。 |
| cli、doctor、platform | 装配入口、探测及操作系统 I/O 细节。 |
| management、command-entry、command-install | 终端状态展示与Python选择、跟随宿主安装版本的稳定命令、用户级命令文件安装。 |

依赖由宿主与具体协议实现指向 Core。
CorePorts 注入时间、身份、环境、授权、配置及客户端构造。
Core 不直接创建宿主 SDK、不退出进程、不读用户密钥。
诊断账本和反馈预算仅使用自有类型，不依赖 Pi 或 MCP 类型。
配置持久化与安装事务集中于具体模块，协议规则不散落到适配器。

## 上游复用边界。

固定上游原始源码与101项回归保留在 `extensions/pi-lsp` 和 `test`。
`client.ts`、`routing.ts`、`format.ts`、`reader.ts`、`process.ts` 被新 Core 实际复用。
上游旧 `manager.ts`、`documents.ts`、`diagnostics.ts`、`tool.ts` 和 `index.ts` 是保留的参考或展示资源，不是新 Codex 的另一套运行核心。
Pi 新入口与 Codex 共用新 Core，不调用旧 Manager 建立第二份实例表。

上游变更如下。

- client 支持依赖注入、原始协议观察、诊断版本、文件能力、动态注册选项、非 UTF-16 拒绝及取消退避。
- reader 增加消息观察和 JSON-RPC 边界校验。
- routing 增加 Windows PATHEXT、Python Scripts、显式 TypeScript 参数与本地版本选择。
- process 增加 Windows 原生进程树终止及 PID 启动身份核验。
- config 标记显式参数覆盖，避免路由默默替换用户参数。

## 资源与取消。

每个真实 MCP 连接拥有一个 Core。
实例键含服务器、解析根和配置摘要，同 Core 启动合并，跨 Core 不声称全机去重。
工作区最多16个，调用候选最多512项和4MB。
空闲十分钟回收实例，崩溃恢复有限次且有冷却。
公开阻塞调用携带 AbortSignal，协议请求具有超时。
Core.close 幂等，取消扫描和监听，再停止 LS。
入口关闭总上界十秒，守护硬收尾上界八秒。
守护不拥有语义和诊断状态，不是全局 daemon。
控制记录使用随机令牌及进程启动身份，CLI 不输出令牌。
未知归属或身份不明的残留只报告，不猜测 PID 杀进程或删资产。

## 文件规模审查。

Core 超过400 NCLOC，保留工作区、实例、文档及诊断订阅这一组共同资源所有权。
删除它会使启动互斥、代次失效和收尾规则分散到两宿主，属于有价值的 deep module。
语义查询已独立提取，磁盘扫描、配置合并和文件事件过滤已分别集中。
CLI 的安装资产分支仍包含编排，但持久化与共享所有权在 assets 内，不新增只转发包装。
semantic 的主查询按能力、协议和呈现划分局部阶段，共享同一候选代次约束。
不为满足行数机械拆分状态机。

未做：跨机器守护与全局 LS 去重，出现明确多机器共享需求时另行设计。

workspace-symbols集中管理Web兼容聚合的流式扫描、真实路径与gitignore边界、资源预算及documentSymbol协议结果转换。
该深模块隐藏文件系统和协议编排复杂度，不引入转发接口或额外Repository。
外部进程与文档同步仍经既有Instance及SemanticPorts进入，聚合不另建LSP连接或文档版本。
ignore 7.0.8是已存在开发依赖树中的规则实现，本次显式列为运行时固定依赖，避免自行实现不完整的gitignore解析器。

紧凑语义首响应由semantic.ts内的纯函数集中约束正文、真实警告和最终JSON字节预算，不另建泛化预算框架或转发层。
详情缓存仍由SemanticQueries持有并按线程和实例代次隔离，压缩输出不改变其生命周期。
