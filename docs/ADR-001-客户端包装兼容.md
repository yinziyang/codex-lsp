# 固定客户端包装兼容修正。

本决策保留 Codex CLI 0.163.0 与源码提交 `83086188ae0614bd882818ff1aa23f3194962012`。
冻结需求主稿 V3.3 不修改。
协调者在 P0-1 实测后批准本修正，用户再次明确禁止修改 Codex 源码。

## 原方案失效证据。

- 固定 `core-plugins/src/loader.rs` 第966至978行对 `PluginManifestFormat::AgentPlugin` 直接返回空 Hook 来源。
- 正式 portable schema 的包能连接 MCP，但不会发现 Plugin Hook。
- 首次不带 portable schema 的探针经过宿主兼容迁移后能发现并正式信任 Hook，但默认不会加载 `mcp.json`。
- 首次模型执行 Shell 后报告 `unknown MCP server 'codex-lsp'`，不判同轮反馈成功。

原始宿主发现、模型轨迹与固定源码摘录保存在实施证据目录 `../outputs/codex-lsp-implementation/p0-1/`。
该相对路径从项目父目录解析。

## 选定包装。

- 使用官方 `.codex-plugin/plugin.json` Legacy manifest。
- 不保留根目录 portable `plugin.json`，避免宿主优先选择不执行 Hook 的格式。
- manifest 显式声明 `mcpServers: ./mcp.json`。
- manifest 显式声明 `hooks: ./hooks/hooks.json`。
- manifest 显式声明 `skills: ./skills`。
- MCP 配置设置 `cwd: .`，宿主按插件根转换为绝对目录。
- Node 参数使用 `dist/cli.js` 相对路径，不依赖 Legacy MCP 未承诺展开的 `${PLUGIN_ROOT}` 或 `${CLAUDE_PLUGIN_ROOT}`。
- 项目工作区仍只取经过校验的 Hook cwd 或语义工具 workspaceRoot，不能从 MCP 默认 cwd 推断。

Hook 运行环境中的 PLUGIN_ROOT 与 PLUGIN_DATA 仍由宿主设置，但本产品同步 MCP Hook 不启动命令脚本。
本修正不增加全局独立 MCP 注册。
本修正不绕过 Hook 信任，不修改客户端，不减少原 P0 功能。

## 更新兼容。

- 更新仍通过同一 Plugin 标识重新 add 整包。
- 更新前保存已验证旧包、用户启禁状态与配置备份。
- 安装后必须在新启动进程确认实际缓存版本、构建哈希与 Hook 信任。
- Hook 内容变化后重新通过 `/hooks` 审阅。
- 不把 portable schema 验证作为固定客户端下完整能力可用的证据。
- 后续客户端支持 portable Hooks 时重新运行 B1、B2 与 B5，再决定迁移，不能只改 schema。
