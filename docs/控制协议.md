# 本机Core控制协议。

0.1.4起新Core使用协议2，令牌、PID启动身份及instanceId校验继续生效。
控制面只绑定127.0.0.1随机端口，不接受任意命令执行。
令牌仅经Authorization请求头传递，不写入CLI输出或公开报告。

```json
{"protocolVersion":2,"id":"请求唯一标识","instanceId":"明确目标Core标识","action":"restart","workspace":"/absolute/workspace","server":"clangd"}
```

- action仅允许status和restart。
- restart必须指定目标Core和它已拥有的工作区。
- server为可选字段，规范标识及语言别名统一调用servers.ts的target转换。
- 指定server时仅重启该Core、该工作区内该Server的全部项目根实例。
- 省略server保留全工作区重启，覆盖该Core、该工作区的全部Server与项目根。
- 不支持隐式选择其他工作区或其他Core，不提供单项目根选择参数。
- 未知Server、无匹配实例、错误工作区、错误身份、错误协议、未知或冲突字段均失败，不退化成全部重启。
- status不接受workspace或server定位字段。
- 成功返回目标Core当前实例状态，PID和代次可用于核对变更范围。
- 只有被选中实例递增代次，调用层级标识和语义详情缓存依所属实例代次失效。

兼容读取协议1注册记录，用于旧Core状态查看及原有全工作区重启。
向协议1 Core发起指定Server重启时，0.1.4客户端在请求前返回Unsupported，要求新启动插件连接。
不能把server字段发给会忽略该字段的旧Core。
协议2 Core要求显式版本2，拒绝旧格式请求。
更新后应关闭旧测试Codex并新启动，再核对实例协议和构建摘要。

CLI入口为 `restart [Server或语言别名] --instance <ID> --workspace <绝对路径>`。
CLI只接受一个可选Server定位参数，重复标志、多个Server及未知剩余参数均失败。
`restart --server clangd`不是受支持语法，会明确拒绝，不能静默忽略。
